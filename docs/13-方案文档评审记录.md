## 二、问题清单

### P0 · 阻断级（已修订）

#### RV-01 默认垂直夸张写错（事实错误）

- **位置**：`10` §2 G2、`11` §七.4、`12` TC-06 证据。
- **问题**：三处写「默认 8.5×」。实际源码 `app/src/data/projection.ts` 为 `DEFAULT_EXAG = 5`，且注释明确记录「曾硬编码 8.5，改默认后 AO 系统性偏强」。原稿直接沿用了过期的 `docs/01`。
- **影响**：验收基线错误；TC-06 用 8.5 做对照会得到错误结论；`11` 的「从 8.5 下调」是无效方案。
- **处理**：全部改为 **5×**，并注明 `docs/01` 的 8.5× 属文档过期；TC-06 对照改为 `1 / 5 / 16`。

#### RV-02 图层开关数量写错（事实错误）

- **位置**：`10` 口径说明、`11` §五、`12` TC-20。
- **问题**：原稿写「13 个开关」「store 9 个 layers 键」。实测：`state/store.ts` 为 **8 个 layers 键**（coast / prov / cityDiv / dash / tierLine / river / rail / road）+ **10 个 labelGroups 键**；`SidePanel.tsx` 实际渲染 **4 + 2 + 2 + 7 = 15 个开关**（`x` / `rl` / `rd` 三组标注未暴露）。`docs/01` 的「13 个」同样过期。
- **影响**：回归清单漏项，可能把「删掉一个开关」当成通过。
- **处理**：统一为 **15 个（8 图层 + 7 标注组）**，并注明 store 另有 3 组未暴露；要求同 PR 修正 `docs/01`。

#### RV-03 坐标系方案不成立（设计缺陷）

- **位置**：`11` §3.2、`10` TA-R02 业务规则 3、`12` TC-04。
- **问题**：原稿写「内部统一 WGS-84；接入 GCJ-02 底图时由 `coords.ts` 单点转换」。**栅格底图瓦片无法在请求时逐点转换**；WGS-84 地形 + GCJ-02 底图会整体偏移数百米且随位置变化，标注与地形必然错位。
- **影响**：一旦按原稿实施，影像模式上线即错位，返工涉及整条瓦片与矢量链路。
- **处理**：改为「**整场景统一到一个坐标系**」三选一：A 天地图（CGCS2000，推荐）/ B 构建期全场景转 GCJ-02 / C 不接底图仅本地晕渲；新增 **D9** 决策；TC-04 增加 5 个已知地标的偏移抽检。

#### RV-04 默认底图与合规要求冲突（合规冲突）

- **位置**：`11` §二 设计取舍表、§四 `BasemapProvider`。
- **问题**：原稿把默认值写成 `'none'`（无 key 本地晕渲），但合规基线要求「用户未指定时默认腾讯地图」。
- **影响**：默认行为不合规；评审时会被直接打回。
- **处理**：`DEFAULT_BASEMAP = 'tencent'`，无 key / 服务不可用时降级 `none`；`10` R02 业务规则补「未指定时默认腾讯地图」。

### P1 · 重要（已修订）

#### RV-05 需求粒度与分期矛盾（可验收性问题）

- **位置**：`10` TA-R03、§四 分期表、`12` §五 门槛。
- **问题**：R03 把「坡度 / 坡向 / 等高线（P0）」与「高程剖面 / GPX（P2）」混在一条需求里；P0 的出门槛却要求 TC-07（含剖面），形成「P0 未做完就不能过 P0」的死循环。
- **处理**：拆为 **R03a**（坡度 / 坡向 / 等高线，P0，TC-06 / TC-07a）与 **R03b**（线路 / 剖面，P2，TC-07b）；P0 门槛只保留 TC-07a，P2 门槛加 TC-07b。

#### RV-06 数据集命名不一致

- **位置**：`11` §3.1（`divisions.json`）vs `10`/`12`（`cities.json`）。
- **问题**：同一份行政区划数据出现两个名字，且未说明是否改名。
- **处理**：**沿用 `cities.json` 扩字段**（新增 `id` / `parentId` / `level` / `source`），不做无收益改名；`12` TC-08 前置同步。

#### RV-07 产物路径契约不一致

- **位置**：`11` §3.1（`data/tiles/`、`data/derived/`）vs `docs/02` 的产物目录 `app/public/data/`。
- **问题**：源数据与运行时产物混写，违反「产物禁手改、由管线写」的边界。
- **处理**：明确「源在 `data/datasets/`，产物在 `app/public/data/`」，表格加前缀说明。

#### RV-08 架构图语义错误

- **位置**：`11` §二 架构图。
- **问题**：影像底图 `A2` 被画成「→ 派生瓦片 → 离线产物」，但正文又说底图是运行时可插拔服务，二者矛盾。
- **处理**：改为 `A2 → 运行时 Provider`（按 D3/D9），另画「若自建影像瓦片则走离线发布」的虚线分支。

#### RV-09 缺瓦片方案关键参数

- **位置**：`11` §3.3（原仅写 `z0..zN`）。
- **问题**：没有投影、瓦片尺寸、级别数、每级分辨率、覆盖范围、命名、缓存、切级迟滞、并发上限——无法实施，也无法写验收。
- **处理**：新增 §3.3 参数表（Web Mercator、256 px、全球 z0–z4 + 亚洲 z5–z8 + 中国 z9–z10、无损 WebP、版本目录、迟滞 0.15、并发 6），并声明「几何分辨率 ≠ 可发布精度」。

#### RV-10 任务切片未映射分期

- **位置**：`11` §八。
- **问题**：S1–S10 与 P0/P1/P2 无对应关系，无法判断「做完哪些切片可以出 P0」。
- **处理**：加「期」列；S7 标注「P0 数据 / P1 交互」跨期。

#### RV-11 缺单网格→分块的切换与回退策略

- **位置**：`11` §六。
- **问题**：新瓦片与现有 `TerrainMesh` 如何共存、何时切换、失败如何回退均未定义，直接关系到 `07` 的共面穿插是否会回归。
- **处理**：新增四条：共存期不同时绘制同一区域、原子切换条件、连续失败 3 次自动回退、回退路径纳入 TC-18。

#### RV-12 境外覆盖的合规路径未定义

- **位置**：`11` §一 范围、§十 风险；`10` D4。
- **问题**：现状用境外 Terrarium 覆盖**整个亚洲**；白名单只解决境内底图，**亚洲非中国区域的 DEM / 底图来源没有合规路径**。这直接决定「全亚洲渲染」是否还能保留。
- **处理**：新增 **D10** 决策与风险行，明确「若禁用境外源，境外只能低精度示意或改合规服务」，并要求界面标注来源与精度。

#### RV-13 性能指标缺测量口径

- **位置**：`11` §九、`12` TC-14。
- **问题**：首屏体积、帧率、瓦片命中率、重复下载没有定义怎么测，无法判定。
- **处理**：补测量口径（body 总和 / navigationStart→首帧 rAF / 60 帧均值 / 稳定 10 s 堆采样 / 命中÷请求 / 同 `(z,x,y,version)` 重复计数），并限定真实 GPU。
