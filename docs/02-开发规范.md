# 02 · 开发规范

## 一、目录职责

```
.
├── .github/workflows/       CI：构建 → 校验 → 部署
├── app/                     前端（Vite root）
│   ├── index.html           唯一 HTML 入口，只留 #root
│   ├── public/data/         管线产出的运行时数据，不入库（由 publish_data.py 写）
│   └── src/
│       ├── data/            投影、球面映射、数据加载、静态数据、导览机位、拾取几何（不碰 React）
│       ├── scene/           R3F 场景：地形网格与着色、矢量/流线图层、标注、相机与拾取桥接
│       ├── ui/              面板与 HUD（纯 React，不碰 three）
│       ├── state/store.ts   zustand，只放离散 UI 状态
│       └── styles.css
├── archive/                 历史实现留档，只读，不参与构建
├── deploy/                  服务器侧资产：nginx 配置、一次性初始化脚本
├── docs/                    文档（编号命名，见 docs/README.md）
├── src/pipeline/            Python 数据管线（唯一能写 build/ 与 app/public/data/ 的地方）
├── scripts/                 开发辅助脚本（Node）：无头校验、功能回归、定标截图
├── tests/                   产物校验（CI 门禁，不依赖浏览器）
├── data/
│   ├── source/              权威输入，入库：国界、省界、十段线
│   ├── datasets/            脚本生成但需入库：cities.json
│   └── cache/               可重下的缓存，不入库：DEM 瓦片、地级市原始 JSON
├── build/                   中间产物，不入库：data.json / data.split.json
└── dist/                    交付物，不入库：静态站点（index.html + assets/ + data/）
```

**边界规则**

1. `src/pipeline/config.py` 是路径的唯一来源。新增脚本从它取路径，**不要**再写 `dirname(dirname(__file__))`。
2. 任何脚本都不许直接改 `data/source/`。要改输入数据，人工替换文件并说明来源。
3. `dist/`、`build/`、`app/public/data/` 是产物，**禁止手改**。产物不对就改源码，然后重新构建。
4. 分层不许倒挂：`data/` 不认识 React，`ui/` 不认识 three，`scene/` 两者都可以用。跨层只走 `state/store.ts`（离散状态）与 `scene/viewState.ts`（逐帧量）。
5. 每个管线脚本**只写自己的产物，绝不就地覆盖输入**。`npm run build` 必须可以重复执行、结果一致——历史上 `split_mask.py` 覆盖了自己的输入 `build/data.json`，第二次构建把陆地掩膜退化成「全是陆地」，海洋被染成土黄。
6. 新增图层/标注：store 的 `layers` / `labelGroups` 加键 → `SidePanel` 加开关 → `tests/verify_build.py` 若涉及新数据文件则加断言。只加数据不加开关，等于做了个永远显示的元素。

## 一之二、前端约定（React + R3F）

架构是 Vite + React + TypeScript + `@react-three/fiber`，但**渲染路径上没有 React 逐帧参与**。

| 约定 | 说明 |
|---|---|
| 逐帧量不进 store | `mix` / `lod` / `camDist` / `selAmt` / `revealed` 放 `scene/viewState.ts` 的可变对象：`useFrame` 写、组件读。一帧一个 `setState` 会把整棵 UI 树重渲染几百次 |
| store 只放离散状态 | 开关、选中省份、当前导览步、太阳方位…… 变更频率是「用户操作级」的才进 zustand |
| 一个组件一族 three 对象 | `TerrainMesh` 只管地形网格，`VectorLayers` 只管线状要素，`FlowLayers` 只管流线光效；不要出现 `Scene.tsx` 里堆 800 行 |
| 着色器扩展走 `injectGlobe()` | 统一在 `data/globe.ts` 注入球面形变；`customProgramCacheKey` **必须**按映射区分，否则两张网格会共用同一份编译结果（`three` 的默认 key 只认材质类型） |
| 补间按时间推进 | 用 `easeInOut(t/dur)` 而不是「每帧 lerp 0.1」——后者在低帧率下会卡在中间态 |
| GLSL 与 CPU 双份映射 | `toGlobe()`（TS）与 `globeGLSL()`（着色器）是**唯一**允许的重复逻辑，改一处必须同步另一处 |
| 新增依赖先算体积 | `three` 已占 651 KB（gzip 172 KB）。加库前想清楚是否值得，能用 20 行手写就别引 |

## 二、命名

| 类型 | 约定 | 例 |
|---|---|---|
| Python 文件 / 函数 / 变量 | snake_case | `prep_data.py`、`build_city_layer()` |
| Python 常量 | UPPER_SNAKE | `LON0`、`BUILD_JSON` |
| Node 脚本（scripts/） | kebab-case | `check-render.js`、`check-func.js` |
| React 组件文件 | PascalCase，一名一文件 | `TerrainMesh.tsx`、`SidePanel.tsx` |
| TS 模块（data/ scene/ state/） | camelCase | `terrainLoader.ts`、`viewState.ts` |
| 变量 / 函数 | camelCase | `lonLatToWorld()`、`setExag()` |
| 常量与 uniform 名 | UPPER_SNAKE / `u` 前缀 | `EARTH_R`、`GLOBE_U`、`uReveal` |
| 文档 | `两位编号-中文名.md` | `03-部署运维.md` |
| Git 分支 | `feat/` `fix/` `chore/` `docs/` + 短横线 | `feat/province-drilldown` |
| 嵌套中间产物 | 小写名词，多阶段用 `.阶段` 后缀 | `build/data.json`、`build/data.split.json` |

## 三、代码风格

**Python**

- 4 空格缩进，单行上限 110，UTF-8 无 BOM，文件首行 `# -*- coding: utf-8 -*-`
- 每个脚本顶部一段中文 docstring：干什么、输入、输出
- 管线脚本保持"可直接 `python src/pipeline/xxx.py` 运行"，不引入需要 `-m` 才能跑的包结构
- 编码/解码这类有坑的地方，**必须在代码里写清为什么**，而不是只写做了什么

**TypeScript / React**

- 2 空格缩进，单引号，语句结尾带分号；`strict` 全开，不用 `any`（实在要就写清楚为什么）
- 组件用函数式 + hooks；`useEffect` 的依赖表要写全，故意漏的加 `eslint-disable-next-line` 并注明原因
- 自定义 `ShaderMaterial` 里的颜色按**线性值**写，屏幕色会经 sRGB 输出转换（见 01 文档「色彩空间坑」）
- 改 `app/src/**` 后必须过 `npm run typecheck`；`npm run app` 里 `tsc --noEmit` 是构建的前置门
- 单帧要做的事按「便宜的先做」排序：先语义剔除（开关/LOD/背面），再做屏幕空间计算，最后才碰 DOM

## 四、数据资产

| 目录 | 入库 | 说明 |
|---|---|---|
| `data/source/` | ✅ | 权威输入。替换时必须写明数据来源与审图号（若适用） |
| `data/datasets/` | ✅ | 由 `prep_cities.py` 生成，稳定且抓取慢，入库避免每次重抓 |
| `data/cache/` | ❌ | DEM 瓦片（约 40MB / 756 张）、地级市原始 JSON，可随时重下 |
| `app/public/data/` | ❌ | 管线产物：地形/掩膜 PNG、data.json、世界底图 |
| `build/` `dist/` | ❌ | 产物 |

新数据源入库前先问三件事：**多大、能不能重新拿到、有没有合规风险**。答案都是"能"的，就别入库。

## 五、Git

**提交信息用 Conventional Commits，subject 用中文**

```
feat: 支持点击省份下钻地级市界
fix: 修复 16× 夸张下交通线被山体吞掉
docs: 补充部署与回滚流程
chore: 前端迁移到 Vite + React + TypeScript
refactor: 路径统一收归 src/pipeline/config.py
```

- 一个 commit 只做一件事；重构和功能不要混在同一个提交里
- 提交前必须过：`npm run build && npm run verify && npm run check && node scripts/check-func.js`
- 主干是 `main`，直接推 `main` 会触发自动部署；非紧急改动走 PR
- **不要提交** `dist/`、`build/`、`app/public/data/`、`data/cache/`、`node_modules/`（`.gitignore` 已覆盖）

## 六、提交前自检清单

```
□ npm run app           tsc --noEmit + vite build 通过
□ npm run verify        产物校验通过（index.html 无内联大数据、assets 齐全、data 尺寸自洽）
□ npm run check         无头渲染无 pageerror / 404，标注零重叠，截图目视正常
□ node scripts/check-func.js   点选/双模式/图层/夸张/导览全绿
□ 改动涉及的文档同步更新
□ 没有把产物或缓存加进暂存区
```
