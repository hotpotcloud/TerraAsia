# 03 · 部署运维

## 一、链路

```
push main ──► GitHub Actions (ubuntu-latest)
                ├─ pip install -r requirements.txt
                ├─ npm ci
                ├─ npm run build     （prep_data → split_mask → publish_data → prep_world → tsc + vite build）
                ├─ npm run verify    dist/ 静态站点校验（门禁）
                └─ rsync + ssh
                      └─► 119.29.189.103 : /var/www/terra-asia/
                              releases/<run>-<sha>/     完整站点目录（index.html + assets/ + data/）
                              current -> releases/…     软链，nginx 的 root 指向它
                          nginx (8159) 对外服务（站点端口，可改）
```

- 触发条件：`push` 到 `main`、`workflow_dispatch`；PR 只构建不部署
- 单次构建约 3–5 分钟（瓦片缓存命中时）
- 目标服务器：腾讯云轻量应用服务器，SSH 用户 `root`，IP `119.29.189.103`
- **站点端口是 8159**（80 不对外）：nginx 监听 8159，CI 冒烟检查与访问地址都带这个端口。端口是**固定值，不开放成 Variable**，写死在 `.github/workflows/build-deploy.yml` 的 `env.SITE_PORT`；真要改，三处一起改：workflow 的 `SITE_PORT`、`deploy/nginx/terra-asia.conf` 的 `listen`、`setup-server.sh` 的第二个参数
- **SSH 端口用默认 22**，workflow 里不出现 `-p`；服务器改过 SSH 端口时才需要在 `SSH_OPTS` 里补 `-p`

## 二、一次性准备

### 1. 服务器初始化（在服务器上执行一次）

```bash
# 把仓库 clone 到服务器，或者只把 deploy/ 目录拷过去
git clone https://github.com/hotpotcloud/TerraAsia.git /root/TerraAsia
cd /root/TerraAsia
sudo bash deploy/setup-server.sh            # 可传目录与端口：sudo bash deploy/setup-server.sh /data/www/terra-asia 9000
```

脚本会做：装 nginx + rsync → 建 `releases/` 与占位版 `current` 软链 → 移除 Debian 默认站点（会抢 80 端口）→ 写站点配置 → 校验并 reload → 本机自检。

### 2. 腾讯云控制台放通端口

轻量应用服务器 → **防火墙** → 添加规则：`TCP:8159`（站点端口；以后配 HTTPS 再加 `443`）。
**这一步漏了，CI 会在冒烟检查环节红**——文件其实已经传上去了，只是外网访问不到。

### 3. 生成部署密钥

```bash
# 本机执行（不要设密码，CI 无法交互输入）
ssh-keygen -t ed25519 -C "github-actions@terra-asia" -f ~/.ssh/terra_asia_deploy -N ""

# 公钥装到服务器
ssh-copy-id -i ~/.ssh/terra_asia_deploy.pub root@119.29.189.103

# 验证免密登录
ssh -i ~/.ssh/terra_asia_deploy root@119.29.189.103 'echo ok'

# 收集 known_hosts（填 SSH_KNOWN_HOSTS 用）
ssh-keyscan -H 119.29.189.103
```

### 4. 配 GitHub Secrets / Variables

仓库 → Settings → Secrets and variables → Actions

**Secrets（必填 1 个）**

| 名称 | 必填 | 值 |
|---|---|---|
| `SSH_PRIVATE_KEY` | ✅ | `~/.ssh/terra_asia_deploy` **私钥全文**，含 `-----BEGIN OPENSSH PRIVATE KEY-----` 与结尾行 |
| `SSH_KNOWN_HOSTS` | 建议 | 上一步 `ssh-keyscan` 的输出整行。不配会回退 `ssh-keyscan` 并在日志里告警（有中间人风险） |

**Variables（都有内置默认值，不配也能跑）**

| 名称 | 默认 | 说明 |
|---|---|---|
| `SSH_HOST` | `119.29.189.103` | 目标服务器 IP 或域名 |
| `SSH_USER` | `root` | SSH 用户 |
| `DEPLOY_PATH` | `/var/www/terra-asia` | 站点根目录（改了要同步 `setup-server.sh` 的第一个参数） |

> 配完 `SSH_PRIVATE_KEY` 就能部署；其余不配走默认值。
> 端口（站点 8159 / SSH 22）**不在**这张表里——它们是固定值，改代码而不是改配置，见第一节的说明。

## 三、发布

```bash
git push origin main        # 自动触发
```

也可以在 Actions 页面点 `build-deploy` → **Run workflow** 手动触发（用于重发或验证配置）。

发布机制：

- 每次构建把整份 `dist/` 上传到 `releases/<run_number>-<sha7>/`（含 `index.html`、带 hash 的 `assets/`、`data/`）
- `current` 是软链，用 `ln -sfn` + `mv -Tf` 切换——**原子替换**，访问端不会读到半份站点
- 只保留最近 5 个版本，更早的自动清理
- 缓存策略：`assets/` 文件名带内容 hash，一年 immutable；`data/` 文件名固定，一小时缓存 + ETag 回源校验；`index.html` 不缓存

## 四、回滚

```bash
ssh root@119.29.189.103
cd /var/www/terra-asia
ls -1dt releases/*/                       # 按时间倒序列出版本
ln -sfn releases/<要回滚到的目录> .current.new && mv -Tf .current.new current
```

回滚不需要重新构建。也可以直接访问 `http://IP/releases/<目录>/` 先确认那个版本是好的。

## 五、排障

| 现象 | 原因 | 处理 |
|---|---|---|
| CI 卡在 `prep_data.py` / `prep_world.py` | DEM 瓦片下载慢 / S3 不可达 | 看日志里 `tiles ok: N/M`；重跑一次即可，已下载的会进缓存 |
| `verify_build.py` 报体积/尺寸异常 | 数据产物没生成，或 PNG 与 meta 不匹配 | 本地 `npm run build` 复现，先看 `app/public/data/` 下文件是否齐全 |
| `tsc` 报错导致构建失败 | 类型错误（`npm run app` 里 `tsc --noEmit` 在前） | 本地 `npm run typecheck` 复现 |
| 部署步骤 `Permission denied (publickey)` | 私钥没配对 / 公钥没装到服务器 | `ssh -i 私钥 root@IP` 手动验证；确认 secret 是**私钥**不是公钥 |
| 部署成功但冒烟检查红 | nginx 没跑 / 防火墙没放通 8159 | 服务器上 `systemctl status nginx`、`curl -I 127.0.0.1:8159`；控制台查防火墙 |
| 访问 404 | `current` 软链断了 | `ls -l /var/www/terra-asia/current`，指向的 releases 目录是否存在 |
| 页面白屏、控制台 `/data/*.webp` 404 | nginx `root` 没指向 `current`，或 `data/` 没上传 | `curl -I http://IP/data/terrain.webp`；确认 nginx 里是 `root /var/www/terra-asia/current;` |
| 换了数据但页面还是旧图 | `/data/` 缓存一小时 + ETag | 强刷一次；或 `curl -sI http://IP/data/terrain.webp \| grep -i etag` 核对 |
| 首屏很慢 | gzip 没生效，或出网带宽不够 | 先 `curl -H 'Accept-Encoding: gzip' -sI http://IP/assets/<file>.js \| grep -i encoding`，应为 gzip；再 `curl -o /dev/null -w '%{speed_download}' http://IP/data/terrain.webp`，轻量服务器常见 3 Mbps ≈ 375 KB/s，3.5 MB 数据就是 9 秒下限 —— 要更快就得上 CDN 或升带宽 |
