# 亚洲三维地形沙盘 · 产品原型说明

> 项目：**TerraAsia** · v0.7
> 交付物：`dist/`（静态站点：`index.html` + `assets/` + `data/`，由 nginx 托管）
> 生成链路：`prep_data.py` → `split_mask.py` → `publish_data.py`（出静态数据）→ `prep_world.py`（出全球底图）→ `vite build`（出站点）
> 前端：Vite + React 18 + TypeScript + react-three-fiber，源码在 `app/src/`
> 工程约定见 [02-开发规范](02-开发规范.md)；上线流程见 [03-部署运维](03-部署运维.md)。

## 一、产品定位

| 项 | 内容 |
|---|---|
| 一句话 | 把「亚洲地形格局 + 中国地势三级阶梯」做成可旋转、可讲、可演示的三维地理沙盘 |
| 目标用户 | ① 中学地理课堂/教研（课堂投屏）② 科普内容生产者（视频素材）③ 政企展厅/沙盘演示（地形底图） |
| 核心价值 | 静态地图讲不清的「西高东低、阶梯递降、大河东流」，用三维起伏 + 分步飞览讲清；本轮把范围扩到整个亚洲，回答"中国在哪里、周围是什么" |
| 使用场景 | 课堂 5–10 分钟导入、展厅循环播放、内容号录屏、教学课件内嵌 |

**范围与主次**：渲染范围为东经 25°–180°、北纬 11°S–80°N（西起红海与地中海东岸，东到白令海峡，北抵北冰洋，南到印尼群岛）。中国仍是唯一视觉主体——境内保留分层设色与全部标注，境外去饱和压暗为冷灰浮雕，只做地理参照。

## 二、产品结构

```
开场（开场动画：从东向西逐级升起，铺满整个亚洲）
 └── 步骤 1 · 亚洲格局 · 中国在什么位置（全景，交代中部高、四周低）
      ├── 步骤 2 · 总览 · 中国三级阶梯（收进中国）
      ├── 步骤 3 · 第一阶梯·青藏高原（4000m+，世界屋脊、大江发源地）
      ├── 步骤 4 · 第二阶梯·高原与盆地（1000–2000m，四大高原 + 三大盆地）
      ├── 步骤 5 · 第三阶梯·平原与丘陵（<500m，三大平原 + 东南丘陵）
      └── 步骤 6 · 江河东流（长江/黄河等跨越阶梯入海、阶梯交界水能富集）
```

每步 = **镜头飞抵 + 目标阶梯高亮（其余压暗）+ 讲解文案 + 对应标注**；支持「上一步 / 下一步 / 自动演示（9.5s 停留）/ 重播开场」。另设三个快捷视角：**亚洲全景 / 聚焦中国 / 当前导览**。

## 四、视觉与数据方案

### 亚洲版的核心取舍：怎么在"铺满亚洲"的同时保住"中国是主角"

| 手段 | 做法 | 为什么 |
|---|---|---|
| 色彩主次 | 中国境内走**分层设色**（绿→黄褐→棕→雪白，饱和度保留）；中国以外陆地按真实高程取同一条色带，但**去饱和 55%、蓝偏、整体压到 0.66/0.72/0.84** | 只降饱和不降亮度，绿色会被推向高亮度的灰，整块大陆发白发平；必须同时压暗才有"底衬"感 |
| 分级压暗 | 肤色编码里给境外陆地单独一档 `tier=4`，片元着色器取固定 0.72 档，**不参与**导览时的一/二/三阶梯明暗切换 | 导览讲第二阶梯时，不该让整个印度半岛跟着变亮 |
| 色差边界 | 「中国=彩色、境外=冷灰」的分界正好落在国界线上，同时把国界线改成**贴地绘制**（v4 是画在 y=0.2 的平面上） | 高原段（喜马拉雅、帕米尔）的国界如果画在水平面上会整条埋进山体里看不见，色差边界就成了无解释的硬边 |
| 边缘消除 | 陆地/海洋都向背景色 `#060d16` 渐隐（陆 0.09·GW、海 0.13·GW 羽化半径） | 亚洲是从地球上切下来的一块矩形，硬边会让整张沙盘看起来像一张贴图 |

### 立体感

- 默认垂直夸张 **8.5×**，滑杆上限 16×；高原边缘、山脊、峡谷的高差一眼可读
- **光照对比拉大**：环境光压到 0.24 左右、直接光 1.08，另加「坡度压暗」（越陡越暗），山脊与沟谷分开；投射阴影与天空遮蔽见下一节
- **每 500m 一条淡等高带**：片元里用 `vElev` 算 `fract(h/500)`，让"多少米"能被读出来
- **法线平滑 2 遍**：陡崖处相邻三角形法线的水平分量左右翻转，直接光照会渲染成一排明暗竖条纹（"城墙鳍片"）；邻域平均后条纹消失、大尺度坡向保留
- **高度连续过国界**：不再对境外做 0.72 压缩（会在国界形成 28% 落差 → 沿边境一圈人造悬崖）
- **DEM 降采样用面积平均（BOX）**：双线性会跳过源像素，在陡崖处产生高/低交替的锯齿

### 光照与阴影（真实感的核心）

早期版本用"一个方向光 + 一盏补光 + 坡度压暗"，本质是**浮雕**：能看出坡向，但看不出"山峰把影子投进山谷"。现在换成三层：

1. **太阳投射阴影（实时，高度场自遮挡）**
   片元着色器从当前像素沿太阳的水平投影步进，每步把射线抬高 `tan(太阳高度角) × 步长`，与高度纹理里的地形高度比较；取全程**最小间隙**做半影阈值（`smoothstep(0, 0.30, minD)`），所以山脊擦光时会出现一条自然的软边，而不是硬邦邦的锯齿。
   40 步 × 0.55 世界单位 ≈ 22 单位，足够跨过任何山体；一旦被挡住立即 break，省掉无效采样。
2. **天空遮蔽 AO（预计算）**
   与太阳无关，只取决于"四周地形挡住多少天空"。加载时按 1/4 分辨率、8 个方向 × 26 步投射，算出地平线仰角并归一化为灰度纹理，着色器双线性上采样。遮蔽上限 0.66——再狠沟谷会糊成黑块，起伏反而看不清。全分辨率逐像素在 JS 里算不动（229 万 × 8 × 26），降采样是必要的取舍。
3. **天空半球光 + 反向补光**
   `skyL = 0.24 + 0.20·(0.5+0.5·n.y)`：朝上的面吃更多天光；再用一盏很弱的反向补光（0.09）避免背光面死黑。环境光不能给多，否则坡向差异被抹平，整块大陆发灰发平。

太阳方位/高度都做成了滑杆（方位 0–360°、高度 6–82°），默认西北高位 315°/40°（制图传统布光）。

**两个必须记住的坑**：
- **波纹频率不能接近像素采样率**。水面最初用 260 周期的正弦扰动，直接混叠成一片大亮斑（远看像海面长了霉点）。压到 40 周期量级 + 按距离衰减后才正常。
- **世界空间与局部空间的向量不能混着点乘**。球面模式下法线已经卷到球面（世界空间），而高度场步进要的是平面网格坐标（局部空间）；一开始用同一个太阳矢量同时喂给两者，`dot` 恒为负，整块地形变黑。

### 平面 / 地球双模式

同一份几何，靠一个 `uGlobe` 系数（0=平面 1=球面）在顶点着色器里连续形变：

```
globePos(p) = (R + p.y) · (cosφ·sinλ, sinφ, cosφ·cosλ)
```

经纬度从平面 `x,z` 反解——平面 z 本来就是墨卡托纵坐标的线性裁剪，常数全部已知，所以**不需要额外的经纬度属性**。国界、河流、交通、省界、标注全部复用同一个 `morphToGlobe()`，因此过渡是一次统一形变，不会出现"地形卷上去、线条还留在原地"。

几个设计取舍：
- **法线要跟着搬运**：用该点的 (东, 天, 南) 基向量把平面法线平行移动到球面，否则地形一上球面就变成平光
- **标注走 CPU 版**：CSS2D 的定位在 JS 里做，`data/globe.ts` 里 GLSL 版（`globeGLSL`）与 CPU 版（`toGlobe`）是同一套映射的两份实现，改一处必须同步
- **地球模式要移动光源**：平面布光用"西北高位"是制图传统，但在世界坐标里"西北"是一个固定方向，亚洲那一面正好背光。切到地球时把太阳移到能照亮亚洲的位置（79°/34°），切回来还原，太阳滑块的数值同步更新
- **过渡按时间推进**（1.6s ease-in-out），不用"每帧向目标插值"——帧率一低，指数插值走不完，地形会卡在"半平面半球面"的中间态（无头渲染时实测过）
- 球面补齐：暗面球体（带晨昏线）、15° 经纬网、菲涅尔大气辉光、1600 点星空；**整颗星球都铺真实地形**（见下节），海洋与极地也是高程数据，不是贴图
- **夜面不能死黑**：晨昏线用 `smoothstep(-0.55, 0.35, dot(n, Lw))` 过渡，夜面保底 0.34 亮度——太硬的终止线会把星球切成"一半黑掉"，太亮又没有昼夜感
- **背面标注要剔除**：CSS2D 没有深度遮挡，球体背面的标签会透过地球显示。用「标注位置单位向量 · 相机方位单位向量 > 0.18」剔除，比做法线点乘便宜且不会误杀侧缘

### 两级精度：全球粗网格 + 亚洲高精叠加

「地球模式要铺满整颗星球」和「中国近景要够细」是矛盾的：单张全球网格按亚洲精度做，纹理就是几万像素见方、几十 MB。

做法是**两张网格同时存在**，不做 LOD 切换：

| 网格 | 范围 | 分辨率 | 用途 |
|---|---|---|---|
| 世界底图 | ±85.05°（正方形墨卡托），z4 瓦片 256 张 | 1024×1024，约 39 km/格 | 铺满球面，提供大陆轮廓与全球起伏 |
| 亚洲高精 | 东经 25–180°、北纬 11°S–80°，z6 瓦片 756 张 | 1536×1493，约 11.2 km/格 | 压在世界底图上，中国及周边的一切细节都来自它 |

- 两张网格用**同一套着色器**，靠两个 uniform 分工：`uEdgeMode`（1=图幅边缘渐隐，只对亚洲这一块生效）与 `detail`（外圈羽化阴影与等高线）
- z-fighting 靠 `polygonOffset(1,1)`（世界底图）+ `renderOrder=1`（亚洲 patch）解决，肉眼看不到接缝
- **平面模式必须先把两层搬到同一坐标系**：两层各自以自己的图幅中心为原点（世界底图中心经度 0°，亚洲层中心经度 102.5°），球面模式靠各自 `lon0/WX` 映射天然对位，平面模式则要显式平移。`TerrainMesh` 收一个 `flatOffset`（= `asia.proj.lonLatToWorld(0,0)`），按 `1 - uGlobe` 淡入，球面时归零。**这一步不能省**：不平移的话世界底图会整体错开约 102°，它的高海拔区（如喜马拉雅、中亚山结）就从下方顶穿亚洲层的平原，屏幕上表现为"整片区域发灰、地形不见了"——`polygonOffset` 只解决共面 z-fighting，解决不了真实高度差造成的穿插
- 平面模式下用户看到的就是"一张完整的亚洲图"，只有地球模式才会看见"整颗星球"
- 代价是两份几何（1024² + 1536×1493 ≈ 340 万顶点）常驻显存；收益是不用写 LOD 切换、不会在缩放时"跳精度"


### 尺度标定（本轮最容易踩的坑）

世界尺寸、相机距离、线宽、贴地偏移四者互相关联。做法是**锁死"每经度的世界单位数"**：

```
U_PER_DEG = 1.965   // 沿用 v4（124 单位 / 63.1°）
WX = (lon1 - lon0) * U_PER_DEG = 155 × 1.965 ≈ 305
WZ = WX * GH / GW ≈ 296
```

因为 u/deg 不变，**垂直夸张比、管径、贴地偏移、LOD 距离阈值全部不用重新标定**，只有"世界变大了 2.46 倍"这一件事——于是相机初始位、`maxDistance`、雾的近远、远裁面统一乘 `K = WX/124`。如果反过来把 WX 固定在 124，中国只剩 50 单位宽，可下钻深度会直接砍掉一半、线体相对变粗 2.46 倍。

### 视觉与动态

- 深色底（#060d16）+ 高程分层设色：绿（<500m）→ 黄褐（500–2000m）→ 棕（2000–5000m）→ 灰白（>5900m 雪线）
- 海面三段渐变：陆架（黄海/东海/巽他陆架这些大片浅海）→ 海盆 → 深海沟；用 Terrarium 自带的海底负高程算真实水深
- 十段线金色虚线、岛礁金色点标记；开场 5.2s 从东向西逐级升起
- 河流沿河道流动光点；阶梯分界线橙色连续光带 + 低频行波（**默认关闭，教学辅助用**）；阶梯高亮时其余压暗至 30–42%；铁路银白、公路玫瑰红细线，均带缓行高光
- **色彩空间坑**：自定义 ShaderMaterial 直接写 framebuffer，不经过 sRGB 输出转换。若用 `new THREE.Color(hex)` 会先转线性空间，渲染色明显变暗偏橙（黄河会变成土褐）。改用原始分量 `rawColor()` 后，屏幕色才等于设计稿的 hex；反过来说，shader 里手写的颜色常量都要按**线性值**给，普遍要比"看上去"的十六进制暗很多
- **贴地渲染（关键工艺）**：所有线状要素（河流/阶梯分界/交通/省界/国界）先对 XZ 平面做样条平滑，再**密集重采样逐点吸附高程**，并按地形网格误差抬高固定偏移量（0.20–0.36 世界单位）。直接用稀疏控制点建样条会「穿山」，在地形三角面与采样值的偏差处被遮住，视觉上就是一条断掉的虚线——抬高偏移 + 重采样后线体才连续

| 省界 | DataV `100000_full.json` | 按省拆分为 33 个独立对象（可点选），C-RDP 抽稀；预计算各省**平均海拔**与**主体阶梯**（栅格化后统计） |
| 地级市界 | DataV `areas_v3/bound/{adcode}_full.json`（逐省抓取，本地缓存） | 33 个省级单元 → **446 个市级单元**，C-RDP 抽稀到 0.013°、仅保留外环；点选省份时按需构建几何 |
| 城市/国家 | 手工整理 | 34 个省会/首府 + 30 个重点城市 + **31 个亚洲国家名**（弱化灰字） |
| 山峰·景区·境外山河 | 手工整理 | 10 座高山雪峰 + 24 座名山 + 17 处景区·湖泊 + **26 处境外山脉/河流/平原名**（最弱一级样式） |
| 交通线 | 手工整理 | 13 条铁路通道 + 12 条国家高速（G 字头），沿主要城市节点连线；**示意数据**，非精确走向 |
| 十段线 | gmt-china/china-geospatial-data | GMT 格式 → 10 段虚线 |
| 河流 | 手绘干流节点（长江、黄河、珠江、黑龙江、松花江、雅鲁藏布江、塔里木河、淮河、辽河、海河） | 近似河道，Catmull-Rom 平滑 + 密集重采样贴地渲染；黄河取亮金黄、长江取亮蓝，保证在黄褐地面上可辨 |
| 阶梯分区 | 教科书标准表述的近似多边形（昆仑—阿尔金—祁连—横断 / 大兴安岭—太行—巫山—雪峰山） | 只在国境内判定；境外一律记 0 档 |

**肤色编码（一张 RGBA PNG 塞进四件事）**

| 通道 | 内容 |
|---|---|
| R,G | 16 位高程（米 + 300 偏移） |
| B | 中国境内存**阶梯档位 ×85**（85/170/255）；中国以外陆地存 0；海洋存**真实水深** ×255 |
| A | 陆地掩膜（海岸羽化）→ 生成后被拆到独立灰度 PNG，地形图 A 恒 255 |

于是 `B ≥ 60 且是陆地` 就唯一等价于「中国境内」，不占额外通道。**踩坑**：canvas 2D 的预乘 alpha 会把 A=0 像素的 RGB 清零，所以掩膜必须拆成单独 PNG、地形图 A 恒 255（`src/pipeline/split_mask.py`）。

**性能与体积**

| 项 | 数值 |
|---|---|
| 顶点 | 亚洲 229 万（1536×1493）+ 世界 105 万（1024×1024） |
| 数据 | `terrain.webp` 1735 KB、`mask.webp` 92 KB、`world.webp` 797 KB、`world_mask.webp` 61 KB、`data.json` 821 KB（gzip 231 KB） |
| JS | `three` 651 KB + `r3f` 282 KB + 应用 62 KB（gzip 后合计约 294 KB） |
| 首屏 HTML | 0.7 KB（薄壳，不含数据） |
| `dist/` 合计 | 4.4 MB |

数据图用**无损 WebP**：R,G 拼 16 位高程，属于数据不是照片，有损压缩会让 26% 的像素在
「境内/境外」判定上翻转，所以只能 lossless；同样像素无损 WebP 比 PNG 小约 30%
（数据 4.8 MB → 3.5 MB）。六个数数组件在启动时**并发**拉取（原来串行：等一个下完才发下一个，
CPU 解码期间带宽整段空转）。
数据与代码分离后，改前端只需重发 1 MB 的 JS，改数据才动 webp；带 hash 的 `assets/` 可以长缓存，
`data/` 一小时缓存 + ETag 回源校验。
轻量高程平滑 + 双侧光，避免垂直夸张下的「碎面 / 过曝」；桌面端可流畅交互，移动端需降网格（见路线）。

## 五、合规要点（重要）

- 边界与行政区划使用 DataV GeoAtlas 标准数据，含台湾省、港澳特别行政区、南海诸岛，十段线单独绘制，未做简化删改
- **中国以外地区不绘制国界**，仅以地形与国名示意，避免使用未经审核的境外边界数据；页面底部已写明
- 页面底部标数据来源与「产品原型」提示
- **正式对外发布/商用前必须**：替换为带审图号的标准地图服务数据（如天地图 GS(2024)0650），并按《地图管理条例》履行送审；不得直接以本原型作为出版/政务发布底图
