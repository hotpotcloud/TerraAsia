# 外部参考：God's Eye View 的可复用资源与方案

> 考察对象：`D:\CODE\github-code\gods-eye\gods-eye-view`（[bilawalsidhu/gods-eye-view](https://github.com/bilawalsidhu/gods-eye-view)，MIT，v0.3.0）
> 考察目的：同属"浏览器里跑的地球/地形可视化"，看有没有能省我们功夫的数据、算法和工程做法。
> 结论先行：**架构不可照搬（Cesium + 后端服务，我们是 Three.js + 单文件），但资源层和工程层有四处高价值可借。**

## 一、两个项目不是同一类东西

| | TerraAsia | God's Eye View |
|---|---|---|
| 引擎 | Three.js（自写地形材质） | Cesium（商业级 GIS 引擎） |
| 形态 | **静态站点**（`index.html` + hashed assets + data），nginx 托管，无后端 | Vite 打包 + Node 服务端代理，需 `npm run dev` |
| 数据 | 离线烘焙的 DEM 高度场（4.8 MB PNG，按需加载） | 运行时流式瓦片（地形 + 影像 + 二十多个实时图层） |
| 目标 | 教学沙盘：讲清三级阶梯 | OSINT 情报台：看实时飞机轮船卫星 |
| 代码量 | 前端约 3k 行 TS / 四层模块 | `src/` 下 2454 个文件 |

因此**不抄架构、不抄引擎**。它跑 Cesium，我们不可能为了看地形背 10 MB 引擎；它靠服务器拿密钥，我们靠离线烘焙。能借的是它踩过的坑、以及它整理过的公开数据。

## 二、可直接复用的资源（价值最高，且许可干净）

### 2.1 Natural Earth 自然地理区多边形 —— 公共领域

`src/data/local_data/natural_earth/regions.json`（1.9 MB）源自
`ne_10m_geography_regions_polys`，共 1046 个具名自然地理实体，按类型分布：
山脉 222、岛屿 455、**高原 72、沙漠 58、盆地 9、平原 30、三角洲 12、峡谷 3**。

我们需要的"四大高原 + 四大盆地"全在里面（实测存在）：

```
Plateau of Tibet        青藏高原
Loess Plateau           黄土高原
Mongolian Plateau       蒙古高原
Sichuan Basin           四川盆地
Tarim Basin             塔里木盆地
Qaidam Basin            柴达木盆地
Kunlun Mountains        昆仑山
Tian Shan               天山
Himalayas               喜马拉雅
Gobi Desert             戈壁
Manchurian Plain        东北平原
```

`marine.json`（633 KB）是 292 个海域多边形，含 Yellow Sea（黄海）、East China Sea（东海）、Sea of Japan（日本海）、Bay of Bengal（孟加拉湾）、Taiwan Strait（台湾海峡）、Gulf of Tonkin（北部湾）等。**缺渤海**——渤海是我们画面上最显眼的一块内海，得自己描或另找来源。

**体积已实测**（拿它的 `regions.json` 按我们的窗口 lon 25–180 / lat −11–80 裁剪，只保留高原、盆地、沙漠、山脉、平原、三角洲、峡谷、谷地、洼地九类，丢掉岛屿与大陆轮廓——岛屿我们已有海岸线数据）：

```
183 个实体 · 10,745 个坐标点 · 180 KB
青藏高原 66 点   黄土高原 49 点   蒙古高原 94 点
四川盆地 41 点   塔里木盆地 50 点  柴达木盆地 29 点
昆仑山 56 点     天山 64 点       喜马拉雅 60 点
戈壁 72 点       东北平原 90 点
```

对一个 4.33 MB 的产物是 +4%，完全可接受。

**为什么重要**：现在 `05-static.js` 里的高原、盆地、平原范围是手写的近似环，面积是估的。换成真实多边形之后，可以做一件现在做不到的事——**用我们自己的 DEM 在真实多边形内做面积加权，算出"青藏高原平均海拔 XXXX 米"**，教学数字从引用变成实测。

**许可**：Natural Earth 为公共领域，无需授权、无需署名（我们照旧写"Made with Natural Earth"）。
**合规边界（重要）**：自然地理区多边形**不含国界语义**，可安全用于地貌范围；但**绝不能**拿 Natural Earth 的 `countries.json` / `states_provinces.json` 当中国国界或省界——那要走标准地图（审图号）。海域名称一律按中国官方表述显示（南海、东海、黄海、北部湾、台湾海峡），不采用数据源里的英文命名，且不作为划界依据；台湾、香港、澳门在数据与文案中都必须表述为中国的省级行政区。

原始数据可直接从 Natural Earth 官方仓库取，不必依赖 GEV 的烘焙产物：
`https://raw.githubusercontent.com/nvkelso/natural-earth-vector/master/geojson/ne_10m_geography_regions_polys.geojson`

### 2.2 真实星表 + 银河 —— 公共领域 / CC BY 4.0

| 文件 | 内容 | 大小 | 许可 |
|---|---|---|---|
| `bright_stars.json` | 耶鲁亮星星表第五版 9096 颗，J2000 赤经赤纬、V 星等、B−V 色指数 | 235 KB | 公共领域（CDS V/50） |
| `milkyway_{px..nz}.webp` | ESO/S. Brunier 银河，6 张 1024² 立方体面，无星点 | 62 KB | CC BY 4.0 |

我们地球模式的星空现在是 1600 个 `Math.random()` 点，颜色随机、亮度随机。换上真星表后：**北斗七星、猎户座、银河带都是真的**，而且能按 B−V 算色温（GEV 的做法是 `COLOR_SATURATION = 0.55`——人眼看到的星星基本是白的，只有极少数带明显色偏，直接上饱和度会像 UI 图钉）。总代价 +300 KB，对 gzip 后 293 KB 的 JS 包来说是一次值得的置换。

### 2.3 免密钥地形瓦片与高程查询接口

- 量化网格地形：`https://terrain.reearth.land/cesium-mesh/ellipsoid`（Re:Earth / Mapterhorn，CC BY 4.0）。Cesium 格式，我们用不上，但说明**这条免费地形链路是存在的**。
- **点高程查询：`https://terrain.reearth.land/heights.json`**，批量传经纬度返回椭球高，无需密钥。

第二个是马上能用的**校验工具**：拿它查珠峰、乔戈里、各拉丹冬、吐鲁番盆地的真实高程，对上我们烘焙网格里同点的高度，就知道平滑和网格化吃掉了多少。GEV 自己也用它做高程基准的 QA（`scripts/qa-height-datum.mjs`，判据是 `|先验值 − 接口值| < 6 m`）。

注意它的节流：官方文档说每次可传 256 点，但实测 87–186 ms/点，256 点会超过 30 s 超时，GEV 最终把批量压到 **64 点/次** 并做 30 天磁盘缓存。我们做离线校验时同样按 64 一批走。

### 2.4 别人的许可证写法

GEV 的 `DATA_SOURCES.md`（134 KB）逐条列了每个数据集的**来源、许可、能否商用、如何署名**，并且把"随代码 MIT、随数据各归各"这条边界写在 LICENSE 的开头。我们目前只有一句"边界数据来自公开 GeoJSON"，这在正式对外时是风险。值得照抄的是**格式**（一张表 + 每份数据一条 provenance 记录），不是内容。

## 三、可借鉴的工程方案（按对我们的收益排序）

### 3.1 按需渲染（renderGovernor）—— 收益最大、改动最小

**它解决的问题**：Cesium 默认每帧都重绘，相机停着不动也烧 60% GPU。GEV 的做法是一个**引用计数的二值开关**：

- 有任何"每帧都在动"的东西（飞机插值、卫星运动、样式渐变）注册了 hold → 连续渲染；
- 一个都没有 → 切 `requestRenderMode`，只在相机输入、瓦片加载、显式 `requestRender()` 时画一帧；
- hold 用 **Set 按 owner id 记账，不是计数器**——某模块重复 hold / 重复 release 也不会把状态搞坏（这是它写在注释里的设计理由，很值得学）。

**我们的现状**：`99-main.js` 里 `requestAnimationFrame` 无限跑，水面波纹（`uTime`）、河流流光、星空缓慢自转、巡讲补间，全都挂在 `uTime` 上——即使相机静止、鼠标不动，也在满帧重绘。课堂场景里这个页面会开着半小时不动。

**落地方案**：改成"脏标记 + hold 集合"。

- 需要连续帧的 hold：巡讲播放中、模式切换补间中、相机阻尼未收敛、用户正在拖拽；
- 其余情况：渲染一帧后停，等 `pointerdown/wheel/keydown`、图层开关、滑块变化、`resize` 触发下一帧；
- 水面/流光的 `uTime` 在静止时**冻结**（视觉上不必动，因为镜头也不动），或给个开关"静水"。冻结还有个附带好处：省电模式下不再有微动干扰看地形。

预期：静止时 GPU 从持续占用降到接近 0，笔记本风扇能停。

### 3.2 相机贴地防护（cameraGroundGuard）—— 我们有个更简单的版本可做

GEV 的坑：飞行取景的高度是**按目的地估计**的，瓦片没到之前只能按海平面猜；丹佛（1600 m）这种地方落地后人就埋进山里了。它的做法是落地后探测相机与目标下方的**实际**渲染表面高度，低于 `MIN_EYE_CLEARANCE_M = 120` 就抬升，最多重试 8 次 × 600 ms（等瓦片流式加载），抬升小于 2 m 就不动（免得无限微调），用户一动鼠标就放弃接管。

**我们反而更简单**：`10-data.js` 里已经有同步的 `sampleHeight()`，不需要异步探测。所以：

- `flyCam` 结束后按落点的地形高度校正一次；
- 每帧（或每 3 帧）把 `camera.position.y` 钳到 `max(当前, 该点地形高 + 净空)`，避免绕轨时钻进喜马拉雅；
- 地球模式下净空按"球面半径 + 地形"换算。

这条现在是**实际存在的 bug 风险**——高倍夸张系数（`uExag`）下绕轨很容易穿山。

### 3.3 标注避让（worldOverlayAllocation）—— 我们 84 个标注正在重叠

GEV 的标注分配在 Web Worker 里做屏幕空间碰撞求解（1405 行 + 381 行测试），核心是：按优先级排序 → 矩形占位 → 冲突丢弃 → 按来源设"cohort 上限"（每个图层每个缩放带最多显示几个）。重算时机是**相机静止后**，不是每帧。

我们不需要 worker（84 个标注），但需要那套策略。现在远景下省会、地级市、景点会互相压字。可以做一个 120 行左右的纯函数：

1. 每项算屏幕矩形（`CSS2D` 元素宽高已知）；
2. 排序键：层级（首都 > 省会 > 地级市 > 景点）→ 距相机距离 → 与视轴夹角；
3. 用 32 px 网格做占位，冲突项降级（缩字号）或隐藏；
4. 相机 `change` 事件 debounce 150 ms 后重算，不在渲染循环里跑；
5. 顺带做**地形遮挡剔除**：把标注点投到屏幕，取 `uHeight` 在该点的高度与视线高度比较，山后的淡出——GEV 的 `globeInView.js` 用 32×18 网格采样判断"地球还占画面多少"，同一种降采样思路。

### 3.4 分享链接（sharelink）—— 教学场景刚需

GEV 用 813 行 + 370 行格式文档做 URL 状态序列化：相机位姿、图层开关、视觉风格、场景 id 全塞进 hash，带版本号与迁移（例如 bloom 强度从 0–100 改到 0–200，旧链接自动换算）。

**我们的场景更简单也更有用**：老师把"青藏高原、正射俯视、关了交通图层、选中青海省"这一屏发给学生，学生点开就是同一屏。字段就六个：机位经纬度 + 距离 + 方位/仰角、视图模式、图层位掩码、选中省、讲稿步号。带 `v=1` 前缀方便以后改格式。

顺带解决另一件事：现在讲稿 6 步的机位是写死在 `60-tour.js` 里的，分享链接等于把"任意机位"变成可传播的东西，学生也能反哺。

### 3.5 模块边界的机械检查 —— 我们目前只有口头约定

GEV 有两支 CI 脚本：`check-import-directions.mjs`（谁不许 import 谁）和 `check-package-boundaries.mjs`（包边界），把架构约定变成**会红的检查**。

我们的 `02-开发规范.md` 写了「分层不许倒挂：`data/` 不认识 React，`ui/` 不认识 three」，但没有任何东西在检查它。ESLint 的 `no-restricted-imports` 就能做，配置成本很低：

- `app/src/data/**` 与 `app/src/state/**` 里 import `react` / `three` / `@react-three/*` → 报错；
- `app/src/ui/**` 里 import `three` / `@react-three/*` → 报错；
- 只允许从 `state/store.ts` 与 `scene/viewState.ts` 跨层取状态。

挂进 `npm run typecheck` 之前的一步，比写在文档里管用。

> v0.6 时期的等价做法是 grep `src/web/js/*.js` 里有没有裸 `window.` / `new THREE.` / `DATA.`——那套模块靠全局作用域串联，v0.7 换成 ES 模块后由 import 关系天然约束，只剩上面的分层规则需要机器检查。

### 3.6 性能基线表的写法

`docs/PERFORMANCE.md` 不是"我们的性能很好"，而是一张**带条件的实测表**：什么机器、什么浏览器、什么视口、DPR、前台还是后台、5 秒运动 5 秒静止、连测三次取中位数，末尾一节"尚未建立的部分"（没测 Windows、没测其他 GPU）。这种写法可以直接搬到我们的 `03-部署运维.md` 或单开一页，等有人反馈"卡"的时候不至于各说各话。

## 四、明确不借的部分

| 东西 | 为什么不借 |
|---|---|
| Cesium 引擎 | 包体 10 MB+，要 `CESIUM_BASE_URL` 静态资源目录，和"轻量教学沙盘"直接冲突 |
| Google Photorealistic 3D Tiles | 要 API key、有商用条款、中国境内覆盖与精度都不可控 |
| Cesium ion 地形/影像 | 要 token，等于把交付物绑在别人的账号上 |
| 二十多个实时图层（ADS-B / AIS / 卫星 / 摄像头） | 与"教学沙盘"定位无关，且都需要密钥与服务端代理 |
| 语音控制 / LLM 导演 | 超范围，且引入服务端依赖 |
| scopeMask（圆形夜视镜效果） | 是它的风格签名，我们的定位不需要 |
| 2454 个文件的组织方式 | 那是多人多年、带 CI 与 QA 矩阵的项目规模；我们 13 个模块是对的粒度 |
