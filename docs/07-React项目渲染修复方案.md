## 三、推荐正式架构

保留现有 React + R3F + Three.js 工程，不将一次性 HTML 作为运行时依赖。

- React UI：顶栏、共享工作面板、图例、详情、帮助及加载/错误状态。
- zustand：用户操作级状态，包括视图、选中省份、图层、太阳、地形起伏和导览。
- 场景层：地图实例、图层装配、相机、球面切换及逐帧调度。
- 地图纯逻辑模块：投影、高程解码、几何生成、法线和材质计算；输入、输出及坐标约定明确，可独立对照。
- 数据和构建层：固定输入、资源版本、无损数据图、产物校验和发布追溯。

复用原型时迁移其经过对照验证的算法或参数定义，接入正式模块；不复制原型页面、隐藏 DOM 控件和另一套状态机。也不为本次修复重写整套架构：优先沿用现有目录和模块，只调整证据指向的实现。

## 四、定位步骤与决策条件

### 1. 建立可重复的对比条件

固定正式项目提交、数据版本、视口、浏览器/GPU、相机位置和目标、地形起伏、太阳角度、图层、动画完成状态，分别记录本地与线上。

对 C、D 两版共用的亚洲平面区域，建立相同输入、比例及机位的隔离对照；C 没有的全球球面和高级光照，使用正式项目对应能力的专项验收，不能因原型没有而跳过。

入口文件名或压缩文件字节不同，只用于定位资源差异。进一步比较元数据和数据图解码后的高程、掩膜、阶梯值及差值分布，再判断数据是否异常。

### 2. 分离数据、几何和材质

先核对网格维度、经纬度到网格映射、像素中心、UV 方向、海陆掩膜、高程单位及显示高程。对选定经纬度输出数值，不依赖画面猜测。

在同一诊断机位临时隔离亚洲地形，使用简单材质观察几何连续性；再比较顶点位置、索引、法线及平滑过程。若几何本身连续而着色异常，再检查阴影、环境遮蔽和颜色链路。

### 3. 单独检查双层覆盖

固定相机临时开关世界层，比较异常区域是否变化，并检查两层在同一经纬度的实际位置与高度。位置原点相同只是其中一项检查。

若证据确认穿插，修复重点是覆盖区的地表归属和边界过渡，例如为精细覆盖区建立一致的覆盖规则；具体裁剪或过渡方式需结合球面和平面验证后选择。单纯增加 polygonOffset、整体压低世界层或永久关闭全球层不能作为最终解决方案。

### 4. 单独检查光照和球面映射

若异常跟随阴影、AO 或太阳参数变化，核对高度采样方向、纹理过滤支持、阴影射线起点与单位、几何/着色器地形起伏同步、法线空间和颜色空间。

球面模式专项检查局部/世界坐标、法线变换、两层位置、球面高度及切换过程；不能用平面正常推断球面已修复。

诊断时可临时关闭某项效果以隔离原因，最终验收必须恢复对应功能。过度平滑、降低起伏或抬亮整体画面只能作为观感实验，不能直接证明缺陷已修复。

### 5. 用证据决定最小修复

每个确认问题记录“触发条件 → 具体实现原因 → 修改位置 → 修复前后证据 → 回归范围”。若多个问题叠加，分别修复和验证，不用“React 不适合”或“都是真实地形”替代结论。

只有在证据证明框架集成本身存在问题时，才调整对应生命周期或接入方式；不预设移除 React/R3F，不在缺少依据时迁移引擎。

## 五、UI 整理与完整能力保留

沿用 05 文档的精简方向，将现有功能归入“图层、画面、导览”，用短文案、折叠说明和上下文详情减少常驻文字。具体布局是待评审设计，不是已经确认或实现的界面。

- 视图入口保留平面与全球球面切换。
- 图层包含现有行政区、自然地理、交通和地名分类，不因整理入口丢失能力。
- 画面包含地形起伏、太阳方向/高度、阴影、环境遮蔽及自动旋转；低频参数可折叠，但仍可找到并使用。
- 导览、相机、选中省份、详情和图层依赖保持可用；面板开关不重建场景、不重置用户状态。

UI 重组与渲染修复可分开开发和复核，但不能将某一中间阶段当成降级版本交付。最终仍以全部目标和现有能力一起通过验收为准。

## 六、数据、构建和部署

继续使用正式项目的数据管线与 Vite 构建入口，不让构建依赖 C 盘绝对路径或未纳管的原型产物。

核查构建数据来源、瓦片完整性、无损编码、依赖版本和可重复执行；发现缺失、损坏或版本不匹配时阻止发布并提供可定位的错误信息，不静默用空高程填补。

保留全球/亚洲数据的产物检查与现有功能检查，按实际修复补充断言，不能为了让构建通过删除全球球面、阴影、AO 的验证要求。评估为固定文件名数据增加版本关联，防止新代码与旧数据混用；具体版本策略在实施前依据当前缓存和发布行为确定。

发布使用同一份已验证完整产物，记录提交、构建和数据标识；在真实部署地址验证完整功能画面。本地正常、HTTP 200、类型检查通过或网格原点对齐，都不能单独作为验收结论。

## 七、实施和完成标准

1. 完成版本、输入和同机位基线，产出数值及画面对照；复现不完整时明确标记，不编写根因结论。
2. 对确认问题实施最小修复，保留正常功能；按问题逐项提供前后证据。
3. 在 React 内完成 UI 分组和文字精简，检查功能可达、状态一致与维护边界。
4. 完成全功能、本地/线上、近景/远景、平面/球面和连续交互回归，再做最终视觉验收。

完成标准是正式 React 项目在完整能力下达到清晰、连续、偏真实的地理展示效果，并具备可持续维护的实现。不能以“已采用某种架构”“关闭后看起来正常”或“首轮暂不支持”替代。
