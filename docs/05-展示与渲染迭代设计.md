# 05 · 展示与渲染迭代设计

日期：2026-11-10。状态：设计草案，待评审；本轮不修改业务代码。

配套文档：`TASK/展示与渲染优化迭代.md`、`06-展示与渲染迭代验收.md`。

## 一、目标与依据

以真实地理展示为方向，让用户进入页面后先看清地形，再按需要选择图层、调整画面或进入导览。减少常驻文字和重复入口，同时保留已有功能。

本方案依据实际 React 项目 `D:/CODE/github-code/TerraAsia/TerraAsia` 的 `app/src/ui/Chrome.tsx`、`SidePanel.tsx`、`state/store.ts`、场景与数据源码，以及用户提供的线上截图。该项目使用 Vite、React、Three.js/R3F 与 zustand，CI 入口为 `.github/workflows/build-deploy.yml`。

工作区中的 `terra-asia/` 是旧单文件原型，不能作为当前线上版本的本地对照。此前用旧原型得到的“本地正常”结论撤回。

### 当前问题

- 标题卡同时展示徽标、标题、副标题；底部长期展示多行范围、数据和用途说明，抢占地图视野。
- `SidePanel` 将省份信息、导览长文、图例、视图模式、机位、光照和大量开关全部纵向堆叠，低频参数与常用操作混在一起。
- “视图模式”和“视角”含义相近但分散；图层与标注开关集中在笼统的“控制”区，难以查找。
- 选中省份会在长面板顶部插入内容，其他功能位置随之变化；图例没有跟随当前可见图层精简。
- 近景有灰色斑块、坑洼观感，需先区分几何穿插、光照、数据和地形比例问题，不能统一归为“真实地形起伏”。

### 已确认与待确认

- 已确认：实际项目同时渲染全球粗地形和亚洲精细地形；底图配置了 `polygonOffset`，两层覆盖关系需要验证。
- 已确认：线上入口 JS 为 `index-Dq13_J2o.js`，检查时实际仓库本地 dist 为 `index-CFKWgsIf.js`，构建产物不同。
- 已确认：线上与本地部分数据文件字节不同；尚未完成解码像素比较，不能据此认定数据损坏。
- 待确认：灰色斑块是否由两层地形穿插造成；需同机位开关底图、检查两层高度与覆盖范围。
- 待确认：原截图所用发布版本、视角、夸张度和光照状态。上述问题须由实际项目复现，不以旧原型代替。

## 二、范围和实施原则

本轮设计覆盖页面信息架构、现有功能收纳、文案分层、状态联动、渲染修复路径和分期验收。UI 调整默认保留当前深色地图风格、已有数据、图层及导览能力。

自然影像、高精度分块、全局搜索、测量、分享、账号与管理后台均为后续候选，不计入已确认开发范围。暂不迁移渲染引擎，不为 UI 整理引入大型组件库。

先完成同版本问题复现与小范围修复，再评估真实感调优；UI 重组不绑定高精度数据升级，也不以遮挡问题区域或过度平滑代替缺陷修复。

## 三、页面布局与信息层级

### 1. 顶栏：统一操作入口

左侧只保留“亚洲三维地形沙盘”短标题。右侧依次组织视图切换、范围选择和工具入口。

- 视图切换：`平面 / 地球`，显示当前选中项。
- 范围选择：统一为一个菜单，保留`亚洲全景 / 聚焦中国 / 当前导览`；自由浏览时显示“自由视角”。当前导览项在导览未打开时不突出展示。
- 工具入口：`图层 / 画面 / 导览`，每个功能只有一个主要入口，点击后在同一个右侧工作面板中展开。
- 更多菜单：操作帮助、数据与说明、界面恢复默认。恢复默认只恢复界面布局，不隐式清除用户的图层和画面参数。

顶栏不再重复展示产品原型徽标和长副标题。工具均保留短中文名，图标辅助辨识；不能依赖鼠标悬停才能知道用途。

### 2. 地图：默认占据主要视野

首次进入默认关闭工具面板，不显示导览正文、光照参数和完整图例。保留地形、必要地名、紧凑顶栏、指北针及简短来源入口。

地图辅助控件集中在右下角一个控件组，放置指北针及回到默认视角；不在其他角落重复增加相同操作。地图背景继续保留现有深色调，面板边框与装饰降低存在感。

底部左侧使用可收起的紧凑图例，仅展示当前已开启且有意义的符号；完整含义按需展开。右下角保留“数据与说明”入口及简短“原型·非测绘用途”提示，完整来源和原有发布限制可直接展开阅读，不能直接删除。

### 3. 右侧工作面板：一次只处理一类任务

桌面端建议宽度 320–360px；标题、关闭按钮固定，内容独立滚动，不让整页滚动。`图层 / 画面 / 导览 / 省份详情`共享一个面板容器，避免多个浮窗重叠。

打开面板时，相机状态不变；标注避让区域同步扣除实际面板占位，避免重要标注藏在面板后。关闭面板只收起 UI，不取消省份选择、不关闭图层、不停止正在进行的导览。

## 四、现有功能重新归类

### 1. 图层

- 行政区划：海岸与国界、省界、地级市界、十段线。
- 自然地理：河流、阶梯分界。
- 交通：铁路、公路，默认折叠。
- 地名标注：山脉、地形区、河流水体、城市、景区、亚洲国家、境外山河。

每行只显示短名称、开关和必要状态；原括号说明放入辅助说明。图层与其标注关系沿用现有逻辑，关闭铁路后不能留下孤立的铁路线名。地级市界仍以选中省份为前提：未选省份时显示“选中省份后可查看”，不创建“开关已开却无反应”的状态。

图层面板默认展开行政区划、自然地理，其他组折叠。首次默认图层组合以“清晰读地形”为目标；具体地名密度须在全景与近景对比后定稿，不在未验证前一次关闭所有标注。

### 2. 画面

常用区只保留“地形起伏”滑块和短说明；现有 1–16 范围作为兼容基础。显示名称避免直接承诺“真实比例”，因为当前横向投影和纵向系数尚未按真实距离统一标定。

高级设置默认折叠，收纳太阳方向、太阳高度、地形阴影、环境遮蔽和自动旋转。用户文案使用“环境遮蔽”，不常驻展示 AO、uniform、自遮挡算法等内部实现词。旋转中的入口明确显示“停止旋转”。

预设作为第二轮方案：`自然观感 / 地貌增强`。预设控制地形起伏、光照和遮蔽，不擅自覆盖行政边界、选中省份或导览进度。手动改动受控参数后显示“自定义”；参数组完成样板评审后再确定数值。

### 3. 导览

进入导览后才展示当前步骤、进度、上一段、下一段和播放/暂停。每步默认只显示短标题及不超过两行的摘要，完整讲解通过“展开讲解”查看；“重播开场”移入导览内的更多操作。

自动导览播放期间，用户主动旋转、平移、缩放或切换范围时暂停自动推进，避免争夺镜头。选择某一步时执行一次对应机位定位，选中省份信息不得被无关 UI 操作清除。

关闭面板不等于退出导览：播放状态在顶栏“导览”入口显示，并能一键暂停。明确点击“退出导览”后停止推进、取消导览压暗，保留当前相机和用户图层设置。

### 4. 省份详情

点选省份后，使用同一个右侧面板展示省名、平均海拔、主体阶梯、省会与取消选择，不再向长工具面板顶部插入内容。只展示现有数据，缺失值显示“暂无数据”。

进入详情时记录此前的工作面板；返回时恢复此前面板和参数。取消选择后移除对应高亮与市级图层，不重置镜头。自动导览期间点选省份，应先暂停导览再显示详情。

## 五、文案和视觉规范

- 默认首屏不展示整段产品介绍、导览正文或数据来源长文；必要署名与用途提示保留简版和完整入口。
- 操作文案以动作或对象为主，如“图层”“地形起伏”“播放导览”，删除重复修饰和括号堆叠；详细解释放到展开区。
- 正文建议 13–14px，标题 16px，操作目标至少 32px；窄屏触控目标建议 44px，不以缩小字体换取空间。
- 面板使用现有深色背景与一套强调色；选中、悬停、禁用和键盘焦点状态必须可辨，不只靠颜色区分开关状态。
- 工具面板切换仅做轻微淡入；地图飞行沿用既有时间补间。尊重减少动态效果设置，持续旋转和导览始终有暂停入口。
- 宽度低于 900px 时，工具面板改为底部抽屉，默认不超过视口高度的 45%；顶栏工具折叠为一个“工具”菜单，保留视图切换。以 390×844、1366×768 和 1920×1080 验收。

## 六、渲染稳定与真实感路线

### 第一轮：确认并消除斑块

1. 以实际仓库同一提交构建本地和 CI 版本，记录代码版本、数据摘要、视图、相机、太阳参数和地形起伏值；数据图比较解码像素，不只比较 WebP 文件字节。
2. 在用户截图区域固定近景，依次关闭全球底图、阴影和环境遮蔽，保存同机位对照。相机须在开场和视图过渡结束后设定，并记录截图前后参数。
3. 若确认底图穿插：明确精细地形覆盖区的唯一可见地表，评估底图覆盖裁剪或连续过渡；平面与球面都验证。不能只加 polygonOffset、整体压低底图或隐藏整个全球层。
4. 若确认为阴影、法线或采样问题：针对确认的环节修复，同时检查 Float 高度纹理的线性过滤支持与降级方案。不能预先把所有花斑归为粗 DEM 的正常表现。
5. 保持编码地形图无损；发布检查加入同版本可追溯信息。`/data/` 当前固定文件名且缓存一小时，需评估版本化 URL，避免新代码与旧数据混用。

本轮不以“页面加载无报错”“层原点已经对齐”代替画面验收；原点对齐不能证明两个不同精度高度场没有互相穿插。

### 第二轮：自然观感样板

优先选择青藏高原—四川盆地和黄土高原—华北平原两个对照区域。统一比例定义，调整地形起伏、天空补光、坡面压暗、雪线、河流宽度与等高线密度；保留山脊河谷，避免通过磨平地形消除一切细节。

先在现有数据和引擎上评审效果，再确定预设。自然观感不等同于卫星影像模式，不能把低精度地形称为近地面实景。

### 后续候选：高精度地形与影像

只有在现有数据无法满足目标缩放范围时，单独立项分块多级细节和真实水系数据。真实影像模式需确认来源、授权、覆盖、配准、缓存和部署成本；不在本轮 UI 改造中默认接入。

## 七、实现边界与状态设计

- `App.tsx`：装配新的顶栏、共享面板、详情与紧凑来源入口，保持数据包装载职责。
- `ui/Chrome.tsx`、`ui/SidePanel.tsx`：按顶部操作、图层、画面、导览、详情拆分 UI；UI 不直接操作 Three.js 对象。
- `state/store.ts`：增加离散 `activePanel` 状态及必要的返回面板记录，替代只有 `sideOpen` 的表达；保留现有图层和参数状态，防止两套面板状态互相矛盾。
- `SceneBridge.tsx`、`LabelLayer.tsx`：接收面板占位和导览暂停信号；逐帧量仍留在场景状态，不进入 React store。
- `TerrainMesh.tsx`、`terrainMaterial.ts`、`terrainLoader.ts`：仅在根因验证后修改对应渲染环节，和 UI 重组分开提交。
- `styles.css`：限定新容器和响应式规则，避免全局格式化与无关样式改写。
- 无新增业务 API、数据库或账号权限；暂不新增本地持久化，刷新后使用明确的默认状态。缺失数据和空状态必须能解释当前不可用原因。

## 八、迭代安排与交付

1. **渲染基线与缺陷定位**：交付实际项目本地/线上同机位证据、根因结论和最小修复方案；无法复现时明确缺少的版本或状态，保持未解决状态。
2. **UI 信息架构重组**：交付精简顶栏、共享工作面板、短文案、按需图例与来源说明。保持现有功能可达，不依赖新增数据完成。
3. **状态与交互联动**：交付省份详情返回、导览暂停与退出、面板遮挡和窄屏规则；验证整理入口后功能没有丢失。
4. **自然观感样板**：交付固定样板区域的参数对比及预设方案，经视觉评审后再扩展，不先承诺高精度或影像升级。

上述顺序是建议实施顺序；本次仅交付设计和验收文档。代码实施、提交、推送和上线均不属于本次文档交付。
